# Симулятор КЗ «Бугры»

Учебный эмулятор пульта оператора и ПЛК комбикормового завода «Бугры» (линия
подготовки зерна и комбикормов, проект ЕФБШ-578.01). Работает в браузере,
без сервера и без установки: интерфейс в стиле сайта [sysat.by](https://sysat.by)
и симулятора ЛПЗС «Родина», логика — повтор программы ПЛК Machine Expert
«Bugry» на JavaScript.

Что можно делать на тренажёре:

* загружать сырьевые бункеры 101–106 из завальной ямы (через скальператор
  или минуя его), с переключением бункеров по ДВУ;
* создавать программы производства (продукт, масса, очередь бункеров ГП),
  активировать их и запускать производство: дозирование на больших (500 кг)
  и средних (100 кг) весах, дробление в двух молотковых дробилках, НСБ,
  смеситель с вводом масла из УДЖК, ПСБ, выгрузка в бункеры 301–308;
* гранулировать: БО-5 → питатель с ПЧ → кондиционер (пар, ПИД по
  температуре) → пресс-гранулятор (наращивание производительности по току) →
  охладитель → просеиватель → бункеры 301–308, 309 или биг-бег;
* отгружать готовую продукцию в автомобили;
* управлять любым механизмом вручную из окна, как на панели оператора;
* имитировать неисправности и смотреть реакцию ПЛК: автомат защиты, обрыв
  ДКС, пробуксовка и сход ленты нории (ДСЛ), подпор (ДП), дверь, авария ПЧ,
  заклинивание, концевики шиберов, свод в бункере, дрейф весов, отказ
  насоса масла, нет воздуха (компрессор), нет пара, забивание матрицы,
  перегрев охладителя, аварийные стопы и пожарная сигнализация.

## Запуск

Откройте `frontend/index.html` через любой статический веб-сервер:

```sh
python3 -m http.server 8000 --directory frontend
# http://localhost:8000/
```

После включения шкафа «ПУСК» не нажат — это общая авария (как на объекте).
Нажмите **«Нажать „ПУСК“ на шкафу»** в правом верхнем углу, затем:

1. **Производство** → «Активировать» у программы → **«Пуск производства»**
   (20 с предпусковой сирены, потом дозирование);
2. **Загрузка БВ** (правая панель) — выберите бункеры и нажмите «ПУСК»;
3. скорость модели — переключатель «Скорость» внизу справа (×1…×20).

Настройки, наработка и база рецептов хранятся в `localStorage` браузера;
«Настройки → Начать смену заново» возвращает исходное состояние.

## Тесты

```sh
node tests/run.js            # все сценарии (~1 мин)
node tests/run.js гранулы    # один сценарий по части имени
```

Сценарии прогоняют модель без браузера (`tests/load.js` загружает модули в
том же порядке, что `index.html`): россыпь из 3 порций до бункера ГП,
гранулирование до бункера 304, загрузка БВ, аварийный стоп, обрыв ДКС со
сбросом, свод в бункере дозатора.

## Устройство

| Файл | Что внутри |
|---|---|
| `frontend/js/plc-lib.js` | Функциональные блоки библиотеки проекта: `Noria`, `Transporter`, `ReverseTransporter`, `Mehanizm`, `Zatvor`, `AutoShiber`, `DVPT`, `DualShiber`, `TVibrator`, `Aspiration`, `Dozator`, `Ohladitel`, `MyPID`, таймеры TON/TOF/TP |
| `frontend/js/plc.js` | Экземпляры блоков (≈75 механизмов) с условиями `next`/`prev`/`canRunAuto` из `PrgLoading`, `PrgUnloadToSms`, `PrgSmesitel`, `PrgUnLoad`, `PrgUnLoadDop`, `PrgGran`, `PrgAsp`, `PrgUnloadToCar`; `MainCycle1` (режимы, аварийные стопы, сброс, сирена) |
| `frontend/js/plc-prod.js` | Программы участков: загрузка БВ, дозирование (`PrgDosingK/D/J1`), конвейер порций, смеситель и УДЖК, выгрузка ГП, гранулирование; команды панели оператора |
| `frontend/js/plant.js` | Установка «за клеммами»: геометрия мнемосхемы, ёмкости, элементы тракта, датчики (ДКС, ДСЛ, ДП, концевики, ДВУ/ДНУ, весы с шумом), разгон и выбег приводов |
| `frontend/js/plant-flow.js` | Движение продукта, технологические процессы (дробление, смешивание, пар, пресс, охладитель), автотранспорт, журнал аварий, цикл модели (скан 20 мс) |
| `frontend/js/db.js` | База SCADA: сырьё, сырьевые бункеры, рецепты, готовая продукция, программы производства |
| `frontend/assets/mach/*.webp` | Рисованные корпуса машин в стиле «Родины» (дробилка, гранулятор, смеситель, кондиционер, охладитель, просеиватель, скальператор, котёл, ёмкость масла, компрессор). В `render.js` (блок «машины-спрайты») для каждого заданы окно-разрез и патрубки в долях картинки: спрайт ставится по точке подключения трубы, а живое состояние (продукт, вращение, пар) рисуется в окне поверх |
| Насыпь в бункерах и яме | `heapG()` в `render.js`: продукт лежит столбиками со слоями сырья; загрузка — струёй в точку загрузки, выгрузка — воронкой над выпуском; склоны осыпаются до угла естественного откоса конкретного сырья (`RKIT.matSpec`) |
| Фактуры сырья | `RKIT.material(prod)` в `render-kit.js`: своя форма частиц и цвет для пшеницы, ячменя, кукурузы, тритикале, овса, гороха, шротов, мела, соли, премикса, МКФ, дрожжей, жмыха, комбикорма, гранул |
| `frontend/js/render-kit.js` | Материалы и типовые детали мнемосхемы: фактуры (оцинковка, окраска, перфорация, бетон), двигатели и мотор-редукторы, фланцы, трубы, воздуховоды, манометры, арматура |
| `frontend/js/render.js` | Мнемосхема на Canvas: машины, продукт по ячейкам модели, частицы в самотёчных трубах, подписи, масштаб |
| `frontend/js/ui.js` | Окна панели (HMI), вкладки «Производство», «Оборудование», «Аварии», «Сигналы ПЛК», «Настройки» |
| `docs/plc/*.txt` | Тексты 77 POU проекта «Bugry», восстановленные из PLCopen XML (LD → псевдо-ST) |
| `tools/ld_decode.py` | Декодер PLCopen XML: `python3 tools/ld_decode.py Bugry.xml docs/plc` |

Цикл модели: `sensors()` (установка → входы ПЛК) → `plc.scan()` (программа) →
`drives()` (выходы → двигатели) → `process()` (продукт) → журнал аварий.

## Что взято с объекта и что эмулируется

Из проекта: структура программ и блоков, условия пуска/останова и
взаимоблокировки механизмов, режимы (`Regim0` ручное, `Regim1` наладка,
`Regim2.x`), аварии блоков, алгоритмы дозатора (4 скорости, «падающий
столб»), смесителя, гранулятора, охладителя; позиции и названия оборудования
— по схемам Э3 и технологической схеме.

Эмулируется (на объекте это делает SCADA или железо): обмен SCADA ↔ ПЛК
(заменён прямыми вызовами окон), база рецептов, физика продукта,
производительности машин, токи и температуры, автотранспорт. Параметры
подобраны правдоподобно, но не являются паспортными данными оборудования.
